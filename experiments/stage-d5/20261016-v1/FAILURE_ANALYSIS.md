# D5 问题与边界

本轮两次正式四档负载、全部回归与默认容器验收均通过，无失败样本被丢弃。

- D4 的监控 HTTP 读取超时通过独立导出线程/tmpfs 快照读取解决；八档 84 次采集均有 Docker/app/MySQL 完整记录，原始 JSONL 保留。
- 找到的是事件循环内大量短事务与冗余状态读取，非单条慢 SQL 或长会话锁等待。只减少审计 I/O，不靠增加连接池、改任务、改 Prompt 或增加 Backend 得分。
- P95/P99 改善但高并发尾延迟仍明显；同步业务存储与 SSE 校验继续保留。更广泛异步化不在本轮扩大实施。
- 内部计时与业务 Trace 有不同口径；CPU/内存峰值是采样峰值。原始 D4 与同日 instrumented baseline 均保留，不能把时间差全部归因于优化。
- 测试运行时与负载运行分开，完整 pytest 与专项回归并行导致总测试耗时不适合作为吞吐对照。原有弃用警告保留。
